# Проверка AntiSLCrush

Просмотрены все девять C#-файлов, проект, зависимости и конфигурация. Ниже — выводы по исходникам; профилирование и проверка на игровом сервере не проводились.

## Выполнено

- Проект переведён на `Microsoft.NET.Sdk`, зависимости — на `PackageReference`. Сохранены `net48`, x64, версии пакетов из рабочего дерева, существующий `AssemblyInfo.cs`, `app.config` и пути `bin/Debug` / `bin/Release`.
- `GameReferencesPath` позволяет передать каталог игровых DLL при сборке. Значение по умолчанию сохраняет прежнее расположение.

## Что ещё стоит исправить

1. **Высокий приоритет — `SpawnObserversForConnectionPatch`.** Неактивные объекты (`!identity.gameObject.activeSelf`) удаляются из `NetworkServer.spawned` вместе с уничтоженными. Неактивность сама по себе не означает уничтожение; после повторной активации такой объект уже отсутствует в реестре. Разделить удаление уничтоженных объектов и пропуск временно неактивных. Также ветка `conn == null` возвращает `true`, передавая `null` исходному методу вместо его блокировки. Проверить спавн после деактивации/активации и подключение нового игрока.

2. **Высокий приоритет — `SecureNetThreading`.** Prefix для `NetworkWriterPool.Get/Return` возвращает `void`: результат `IsThreadSafe` игнорируется, исходный метод продолжает работать с пулом из фонового потока. Защита здесь только диагностическая. Простая замена на `bool` для `Get` тоже опасна: пропущенный метод не выдаст корректный writer. Нужна согласованная стратегия работы с вызывающим кодом: перенос сетевой операции на главный поток либо явный отказ до обращения к пулу. У `NetworkConnection.Send` результат проверки уже используется.

3. **Средний приоритет — `Scp330BagOnAddedPatch`.** Единственный статический таймер ограничивает все экземпляры сумки и всех игроков. Два независимых добавления за 10 мс блокируют второе. Перед изменением выяснить, защищает ли патч от рекурсии или от частых вызовов; затем ограничивать соответствующий экземпляр/операцию. Проверить одновременную выдачу нескольким игрокам.

4. **Средний приоритет — `Main.Log`.** `Debug.LogWarning` вызывается всегда, даже при выключенном `Config.Debug` и срабатывании ограничения для `Logger.Error`. Ветка debug/error также пишет сообщение, поэтому одна проблема может порождать два вызова логгера. На повторяющихся ошибках это лишние форматирование и вывод. Определить желаемый канал и применять ограничение до записи во все каналы. В `SecureNetThreading` каждый сбой дополнительно строит и фильтрует полный stack trace; ограничивать частоту нужно до его построения.

5. **Средний приоритет — списки из пула.** `BroadcastToConnectionPatch`, `ReserveAmmoSyncUpdateDeltaPatch` и `SpawnObserversForConnectionPatch` возвращают арендованные списки только при нормальном завершении. Исключение после `Rent` пропускает `Return`. Обернуть срок использования списка в `try/finally`, сохранив исходное распространение исключения. Проверить исключение в сериализации/отправке после обнаружения первой проблемной записи.

6. **Низкий приоритет — `OnTransportDataPatch` и жизненный цикл.** Список неизвестных ID хранится до перезапуска раунда. При ожидаемых нескольких ID за раунд замена коллекции без измерений не обоснована. Для длительных раундов оценить число уникальных ID под нагрузкой; если рост существенный, выбрать ограниченную стратегию дедупликации. При `Disable` кэш также не очищается; можно очищать его при отключении плагина.

## Дополнительные наблюдения

- В `ReserveAmmoSyncUpdateDeltaPatch` лямбды не захватывают переменные; переписывать их в отдельные методы ради предполагаемых аллокаций не требуется. Сам патч полностью заменяет игровой метод, поэтому изменения алгоритма нужно сверять с конкретной версией игры.
- `Config.cs` и `Properties/AssemblyInfo.cs` не содержат горячих путей, требующих оптимизации.
- Версия плагина в `Main` — 3.1.1, версии сборки в `AssemblyInfo` — 1.0.0. Это существующее различие сохранено; можно отдельно согласовать политику версий.
- Сохранён пользовательский `YamlDotNet` 18.1.0. LabAPI 1.1.7 объявляет зависимость от 11.0.1; успешная компиляция не доказывает совместимость сериализации на сервере. Имеющийся binding redirect библиотеки не гарантирует его применения загрузчиком сервера. Проверить загрузку и сохранение конфигурации на целевом сервере.

## Проверки

- Release и Debug: сборка с локальными игровыми DLL.

Изменения C#-кода отменены по запросу пользователя. Прежние изолированные проверки изменённых обработчиков к текущему коду не относятся. Сохранена только миграция проекта; рекомендации выше не реализованы.
